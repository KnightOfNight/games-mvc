DEVIATIONS AND RECORDED FINDINGS
  D1. Cart-stock carve-out (seed). The brief pins the salve at "no vendor
      entries" (§11.2b, §13.3), but the standing #43 rule auto-stocks
      EVERY consumable ItemDefinition on both ring street carts on every
      reseed, with a seed-verification set-equality check enforcing it.
      The two directives are contradictory; the brief's pinned end state
      won. Implemented as a narrow documented carve-out:
      CART_STOCK_EXCLUDED = {'weak-mending-salve'} honored by both the
      stocker and the #43 verification check. First-ever exception to the
      every-consumable rule.
  D2. Salve base_value. The type-wide consumable back-fill (12 cp) in
      _seed_items flipped the salve's authored 15 on every run (reseed
      non-idempotent). The salve joins the authored base_values dict at 15
      — the repair-kit precedent, verbatim.
  D3. dot_vitality converted to change-only with actual-delta lines. The
      v26.0 closeout pinned dot_vitality byte-unchanged ("Dying = ruled
      exception"), but this brief's §5.3 invariant ("a tick that changes
      nothing is genuinely silent") and §9.2 ("its ticks on emptied bars
      are no-ops under the change-only doctrine") require the conversion —
      without it a persisting curse dot on a dying character would
      re-trigger the fall (dying_since reset, repeated fatal-blow lines)
      every round. Newly-reaching-0 is a change, so the fall fires exactly
      once. Both v26.0 dot_vitality pin tests still pass as written (their
      setups make actual == nominal).
  D4. Bar-cut mechanics. The brief says "cut the bar's max through the
      standing bar-law rescale; store the flat max-delta on the instance."
      The standing rescale RECOMPUTES maxima from the stat formula, so a
      free-standing cut would be silently erased by any mid-curse gear
      equip, stat spend, or level-up, breaking exact reversal and the
      §9.2 refill-to-cut-max semantics. Implemented so the cut lives
      INSIDE every max recompute: active_bar_cut_totals feeds
      bar_rescale_updates (new vit_cut/lon_cut params, floor 1),
      rescale_bars_for_gear, the cmd_spend path, and recalculate_bars
      (level-up fills to the CUT max, floored at 1). All pinned invariants
      hold (mid-curse rescale keeps the cut — tested).
  D5. Heal-ceiling breadth. The brief's §6 enumerates the instant restores
      and hot_vitality ticking as enforcement points, under the general
      clause "any vitality-increasing write on the target clamps."
      Implemented the general clause: passive regen (Phase 4) and
      lifesteal are also clamped — without the regen clamp the pinned
      floor-hold "silence" is impossible out of combat (regen would lift
      the bar above the hold every tick and the drain would re-announce
      every round, forever). execute_death's refill is deliberately
      exempt per §9.2.
  D6. §8 equip-path audit finding. Two non-player paths set
      is_equipped=True: the door's _dress (outfit restore) and
      _equip_item_admin. Both are documented admin bypasses (the v25.7
      sudo-unequip precedent) — a door equip does NOT spring a latent
      curse; in-code comments added at both sites.
  D7. Door edit_item mirror (§10). The door's edit whitelist refuses
      unknown keys, so the new curse fields are read-only by construction
      — the correct posture (lifecycle is engine-owned); NO new editable
      keys were added, and therefore the sudo bot's edit_item schema
      needed no mirror change. The item READ payload gains latent_curse
      (slug), active_curse (id), memorial_description.
  D8. Expiry-sweep null skip. "The expiry sweep must skip null" was
      already true by construction — expires_at__lte=now excludes NULL by
      SQL semantics. No code change; noted for the record.
  D9. Playtest checklist notes (flagged for the operator BEFORE the
      playtest; the steps' own stop-and-report forks govern):
      (a) Step 8 says the Gravekeeper's Hold "drains 8/round"; the §11.2
          component table (authoritative per the standing rule) gives
          magnitude 8.0/4.0, i.e. 12/round at Mk 1 (8 + 4x1). Expect 12s.
      (b) Step 11 expects the item to survive sudo removal ("item clean,
          unequip free, no re-spring on re-equip"), but the standing sudo
          removal path (the door's remove_item, §9.1's named site) DELETES

          all execute (tested), and then the item is gone. §9.1 was
          implemented exactly as specified; the step's expectations
          cannot be observed on a deleted item. If the intent was an
          effect-only removal surface, that is a design-session question.
  D10. EffectRefused import shape and the MC record: the combat_action MC
      record gains a 'curse_factor' key only when a damage_cut is active
      (record honesty for the scaled final); additive, never load-bearing.
  D11. Playtest-prep-found fix (2026-09-16, before step 8 ran): the #151
      aggregate heal path (`use`/`heal` on instant vitality restoratives)
      writes vitality through its OWN atomic UPDATE in
      _apply_aggregate_heal — a third vitality-heal write path the
      brief's §6 enumeration missed; the heal ceiling did not cover it,
      so a draught would have healed straight past a floor hold (playtest
      step 8 would have failed). Fixed in-session under the brief's
      general clause ("any vitality-increasing write clamps"): the
      aggregate UPDATE gains the Least(max, Greatest(current, hold))
      ceiling, and consumption planning stops at the effective headroom
      (min(deficit, hold − current)) so a hold never mass-consumes
      draughts for nothing — while `covered` stays measured against the
      true full-bar deficit, so the full-heal fold never fires under a
      hold. One new test (AggregateHealCeilingTests); suite 1029 → 1030,
      full suite green. Commits: see the ledger addendum below. Test
      authoring note: the `use` verb takes a numeric-only quantity (v22
      grammar) — the test's first draft used `use all` and never resolved.
