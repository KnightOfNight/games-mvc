DEVIATIONS AND RECORDED DECISIONS (none silent)
1. test_mc_egress.py pins 'read-only' -> 'unknown-frame': the brief-ruled
   supersession, not drift (brief §4).
2. Move visit sequencing: the brief has the door "record the visit" AND the
   moved branch "record the visit + announce zone completion". Recording in
   both places would make the branch's announce dead code (the door's row
   would always precede it). Implemented the respawn division of labor: the
   door records the visit only for OFFLINE targets; online targets' visit is
   recorded by their consumer's moved branch, so a first visit announces zone
   completion exactly like a walked arrival. A disconnect between the
   presence check and delivery self-heals at next connect (the #50
   connect-time visit).
3. Strip/dress "status refresh" mechanism (brief specifies the outcome, not
   the path): a 'refresh_status' player_message branch beside 'moved' calls
   send_status_refresh() — the narration line rides the same event.
4. Same-room move (target moved to the room they already occupy): the
   left/arrived broadcasts are suppressed (both would land in one room about
   a player who never left); the moved line + full re-render still sent.
5. 'internal' result error code (not in the brief's vocabulary): an
   unexpected handler exception refuses the frame with error 'internal' and
   keeps the connection alive, logged — defensive, so a server bug cannot
   kill the door or hang a frame.
6. Unidentifiable artifacts are created is_identified=False (the mystery
   name/description cannot render otherwise); identified artifacts
   is_identified=True. Interpretation of the §5.4 table, asserted in test.
7. create_artifact validation is strict: unknown spec keys, damage keys on
   non-weapons, and armor_base on non-armor are refused bad-params (the
   table's requirement column read as exhaustive).
8. Gift/artifact result data shapes ({item_id} / {definition_id, item_id},
   move {room:{...}}): the brief left action result data unspecified except
   answer/strip/dress; minimal useful shapes chosen and pinned in tests.
