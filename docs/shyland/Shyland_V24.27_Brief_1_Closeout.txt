Deviations & notes

1. STEP 4 REQUIRED NO CODE CHANGE — the brief's premise ("nothing closes a
   character-empty session ... the session would tick forever holding its
   NPCs") is factually incorrect. The combat pass has closed
   empty-participant sessions since combat v1: at the next round boundary
   the participants load returns an empty character list and the
   `if not characters or not npcs` branch closes the session through
   close_session — is_active=False plus release_session_npcs (NPC release
   added at v23 B1, #25) — i.e. within one combat round (<= 3 engine
   ticks), not never. This existing code is exactly the brief's directed
   implementation: same trigger ("the participants load already fetches
   the character list — an empty list is the trigger"), same standard
   close path, same #107 query discipline (no per-session count query).
   Verified empirically before concluding: brief test 7 was written first
   and PASSED against the unmodified engine. Action taken: behavior
   test-pinned (test 7), architecture doc documents it as verified
   pre-existing, zero engine changes. The brief's correct observations
   stand: the v24.19 self-heal checks the NPC side only, and the stale
   sweep never fires for such a session (last_tick_at keeps advancing) —
   the round-boundary guard is what covers the character side.
