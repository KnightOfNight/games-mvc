SUMMARY
Brief 1 applied in full. A terminally failed live sudo request is no longer
silent while the bot is up: the _worker choke point logs a classed warning
(failed (persistent|transient) — reporting to the admin, traceback retained,
UTC-Z) and delivers exactly one fixed in-pane line to the requesting admin
via the door's answer action in sudo's voice. classify_failure(exc) is
duck-typed on getattr(exc, 'status_code', None) — 400/401/403 => persistent,
everything else including no status => transient — provider-agnostic, no
anthropic import at module level. The is_admin pre-check query failure now
raises RequestFailed through the same choke point (transient); a genuine
non-admin still drops silently, byte-identical. The report path never
raises: _report_failure wraps its _deliver call; delivery failure logs and
stays quiet (the exempted bot-effectively-down case). Conversation store,
model-chosen silence, reconnect/kill-switch states, and the #308 bounce all
untouched.
