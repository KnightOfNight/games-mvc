## 2. Design rulings (binding — operator-confirmed 2026-07-29, recorded on #162)

1. **Cooldown: 15 minutes → 5 minutes.** `Character.home_cooldown_seconds` default goes `900 → 300`. Completion-only consumption is unchanged: the clock starts only when the traveler lands at the Heart; interrupted or canceled countdowns never consume it.
2. **Existing characters update unconditionally.** The field is a per-player override, so the default change alone only reaches new characters. A data migration sets **every** existing row to `300` — including admin-overridden values ("then we know they're right"). The earlier hedge about preserving deliberate overrides is superseded.
3. **Countdown: 15 seconds → 10 seconds.** `HOME_CADENCE` goes `(7.0, 5.0, 3.0) → (3.0, 4.0, 3.0)`: start line at t=0, mid-pool line at t=3, late-pool line at t=7, arrival at t=10. **All four authored beats are retained** (start / mid / late / arrival — no pool content removed), and all three `broken_by_violence` checkpoints are retained, now landing at t=3/7/10.
4. **Balance ruling of record:** 5 seconds was considered and rejected as near-instant escape; 10 is the ruled value. `home` remains refused in combat and broken by combat entry mid-countdown — no gating changes.
5. **No wording changes.** `HOME_COOLDOWN_POOL`'s "Give it a few minutes" stays accurate at 5 minutes; the remaining-cooldown parenthetical (`Nm`/`Ns`, ceiling) formatting is untouched. The countdown stays a class constant — no per-character data for it.

The GDD already records these rulings under `(v23.4, #162, pending implementation)` markers (§2 special-travel bullet, §2.11 Home — the Hearth Command). **This session never edits GDD source** — the closeout session sweeps the markers.

## 3. Implementation

All code lives in `django/src/apps/shyland/`. Blast radius: `models.py` (one field default), two new migration files, `consumers.py` (one constant + its comment), tests.

### 3.1 Model default (`models.py`)

`Character.home_cooldown_seconds` (`models.py:277`, v22 B3 / #57): change `default=900` to `default=300`. The field type (`PositiveIntegerField`), help text, and the companion `home_last_completed` field are untouched.

### 3.2 Migrations (exactly two)

1. **Schema migration** (`0038_…`): generated by `make makemigrations APP=shyland` from the default change — an `AlterField`. Generated files are never hand-edited; commit it as generated.
2. **Data migration** (`0039_…`): a separate authored migration following the app's existing `RunPython` precedent (e.g. `0023_boss_scaling_factor_corrections.py`), setting `home_cooldown_seconds = 300` on **all** `Character` rows unconditionally (a single queryset `.update()`, no filtering). Reverse is a no-op (`RunPython.noop`) — the pre-migration per-row values are deliberately not preserved (ruling 2). Use the historical model (`apps.get_model('shyland', 'Character')`), never the live import.
3. Migration files sync to the local filesystem via the enhanced make target and are **committed** (standing rule). `migrate` runs regardless — a deploy covers it (§6).

**Expected update count:** every `Character` row (the count is small — report the actual dev-DB number in the closeout against `Character.objects.count()`; the two must be equal). This is an update, not a deletion — no deletion count applies.

### 3.3 Countdown cadence (`consumers.py`)

`HOME_CADENCE` (`consumers.py:2763`): `(7.0, 5.0, 3.0)` → `(3.0, 4.0, 3.0)`. Update the comment above it (`# Cadence to the three authored beats, then completion at t=15.`) to say t=10. Nothing else in the home task changes: the beat structure (start line → sleep → mid pool → sleep → late pool → sleep → completion), the three `broken_by_violence` checkpoints, `HOME_VIOLENT_LINE`, `HOME_MOVE_CANCEL_LINE`, `HOME_COOLDOWN_POOL`, the gates order, the witness/ceremony lines, and the delayed-action registry are all untouched.

## 7. Operator playtest checklist (dev stack)

Ready after §6's `make deploy-dev`; all steps on the dev stack:

1. From a room away from the Heart, `home` → four beats in order: start line immediately, mid-pool line ~3s, late-pool line ~7s, arrival ~10s. The wait should feel noticeably shorter than before.
2. After landing, walk one room off the Heart and `home` again → wry cooldown refusal ending in the exact parenthetical, now showing ≤5m (e.g. `(4m cooldown rem.)`).
3. Wait out the 5 minutes → `home` works again (the cooldown really is 5 minutes now).
4. Start a countdown, then move mid-count → the cancel line prints and the move proceeds; `home` immediately after works (interruption consumed no cooldown).
5. Start a countdown, then attack something mid-count → the violent interrupt line; `home` immediately after works (no cooldown consumed).
6. In combat, `home` → refused (warn), unchanged.
7. Django admin spot check: any existing character's `home_cooldown_seconds` reads 300 (the data migration reached the old rows).
