Part A — kill path M2M-wide. In execute_actions' kill block, immediately
after the killer's-session removal (session.npcs.remove(npc)): the dead
NPC's other active sessions (npc.combat_sessions.filter(is_active=True)
.exclude(pk=session.pk)) each drop the row. A session left with no living
NPCs closes on the standard end pattern in the same round — is_active=
False, focus_npc=None, save, release_session_npcs, "Combat has ended."
(reward) and a fresh status per member via the round's pk-addressed
messages/statuses lists, and its fight-clear payload after the round
(closed sessions accumulate in ended_sessions, threaded out of
execute_actions as a fourth return element; build_fight_payloads on an
inactive session already returns the clearing payload). A session that
retains living NPCs but had the dead NPC as focus reassigns to its next
living NPC (canonical (spawned_at, pk) order) with "You turn your attacks
on {name}." (combat), the name ordinal-composed via npc_display_name
against that session's own remaining live NPCs. The killer's session flow
is untouched; no room broadcast changes.

Part B — loop-head self-heal. The active-sessions loop opens each
iteration with a fresh DB read (read_session_state: current is_active +
living-NPC existence — never the prefetched cache, stale for sessions
Part A closed earlier in the same tick's loop). No longer active ->
silent continue. Active with zero living NPCs (dead rows attached or no
rows at all) -> immediate close on the standard pattern (self_heal_close:
is_active=False, focus_npc=None, release_session_npcs, then "Combat has
ended." (reward) + fresh status + fight-clear per member), logged
"Combat session {pk} closed (self-heal: no living NPCs)", then continue —
update_session_tick never runs for it, so a zombie never refreshes its
own last_tick_at and the stale sweep is restored as backstop by
construction. The stale sweep itself (get_stale_sessions/close_session)
is untouched. release_session_npcs untouched per ruling 4.
