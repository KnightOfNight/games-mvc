DEVIATIONS
----------
1. §5 — THE HELPER'S RETURN SIGNATURE. The brief specifies sweep_corpses
   returning "an ordered list of (text, category) tuples". It returns a PAIR,
   (messages, room_lines).

   Reason: the sweep's corpse-disposal announcement ("X slowly disappears.")
   was never a personal line — _maybe_dispose_corpse emitted it as a room-wide
   channel_layer.group_send. It therefore cannot be a (text, category) tuple
   bound for the looting character, and a synchronous transport-agnostic helper
   cannot send it itself. The second list carries it, and each transport
   broadcasts it on its own channel (the consumer via group_send, the tick
   engine via broadcast_to_room / the room_messages accumulator).

   Order within each stream is unchanged; cross-stream ordering was never
   deterministic in the first place, since one path is a direct send and the
   other a channel-layer round trip. This is the signature adaptation §5
   explicitly permits ("if preserving behavior exactly requires the helper to
   take an extra collaborator, pass it in").

   The §5 regression bar was met with no test edited: the existing loot suite
   (653) passed immediately after the extraction commit.

2. §4.4 vs §4.5/§12 — AN INTERNAL INCONSISTENCY IN THE BRIEF, implemented as
   written and recorded here rather than silently reconciled.

   §4.4 mandates a _set_plunder_mode that writes both the DB row and the cached
   attribute, justifying it as matching "cmd_brief's shape". It does not:
   _set_brief_mode writes only the DB row, and cmd_brief maintains the cached
   attribute. §4.5 and §12 then state the setters "now uniformly write only the
   DB row" — which the new setter makes untrue.

   Implemented exactly as §4.4 specifies (the brief gives the code verbatim and
   says "leave both"). It is harmless: the cached field it writes is its own, so
   the #250 failure mode cannot recur there. The architecture doc records the
   accurate position — the three older setters write only the row, and
   _set_plunder_mode is a deliberate belt-and-braces exception — rather than
   repeating §12's inaccurate sentence.

3. §6.2 — a wording nit, no behavioral effect. The brief describes the engine's
   accumulator as (char_pk, text, category, status); the fourth element is
   actually `event` (status is passed separately as None at the flush). The
   brief's instruction to append (char_pk, text, category, None) is correct
   either way and was followed verbatim.

4. §1 — cosmetic: the section is titled "Two things" and lists three.
