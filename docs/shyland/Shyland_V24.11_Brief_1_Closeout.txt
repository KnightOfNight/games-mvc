===========================================================

SUMMARY
-------
Identification is now a property of holding, per the #80 ruling of record
(2026-08-04) and the brief's six binding design rules. Pickup identifies and
drop re-veils at the ownership-transfer choke points only: transfer_to_character
and do_loot_item gained the identify-on-take flip, mirroring transfer_to_room's
existing re-veil; all three carry the is_unidentifiable guard (an unidentifiable
item's is_identified is never written by any path). do_loot_item composes its
looted name AFTER the flip so the looted line names the real item the player now
holds. The veil hides every info suffix: get_item_suffix returns '' for
unidentified items (killing durability %, BROKEN, and bag carry-bonus at every
compose_item_line site in one place) and _details_cell gates its durability
segment on is_identified exactly as rarity already was — the unidentified line
is mystery name + [Bound|Unbound] only. Examine is close inspection: an
unidentified (non-unidentifiable) item renders the full identified detail block
byte-identical to examining it identified, via an in-memory-only
is_identified = True with no .save() (output-only per #80; the room listing
keeps the mystery name until pickup); the is_unidentifiable mystery block
tightened to composed line + blank + description + no-method line, with the
redundant "(You cannot determine anything further about this item.)"
parenthetical deleted. Resolution and tab completion continue to match visible
names only — a re-veiled item's real name neither resolves nor completes.
Lasting mystery is now exclusively is_unidentifiable. Seed data untouched (the
veil is the drop mechanic, not a ground-state invariant).
